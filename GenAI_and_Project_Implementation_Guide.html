3. Gen AI Implementations (AWS Bedrock + Python)

Implementation 1: AI Pipeline Failure Diagnostic Utility

Problem: Raw PySpark/Glue CloudWatch logs contain 500+ lines of Java/Python stack traces, slowing triage.

Solution: EventBridge detects Glue job failure ➔ Lambda extracts log stream ➔ Lambda invokes AWS Bedrock (Claude model) ➔ Bedrock generates concise 3-bullet root-cause diagnosis ➔ Sent to Slack/Email via SNS.

🚨 Sample Alert:
• Root Cause: SchemaMismatchException — Column incurral_date format error.
• Affected File: s3://prudential-vendor-inbound/vendor_b/claims.csv
• Action: Update JSON schema config for Vendor B.

Implementation 2: LLM-Assisted Schema Mapping Utility

Problem: Vendor file headers change unexpectedly (e.g. policy_no ➔ policy_number).

Solution: Lambda reads file header ➔ AWS Bedrock maps header columns to target Aurora/Db2 schema attributes ➔ Auto-generates candidate JSON extraction mapping config for developer review via Git PR.

4. AWS Aurora & RDS Database Operations (GitHub Actions)

Codified table DDL and schema migrations into Git. Merges to Dev/QA trigger GitHub Actions workflows to securely connect to AWS VPC and provision/update Aurora cluster and RDS tables automatically — zero manual AWS console edits required.

5. PySpark Performance Optimization (30m ➔ 5m)

  • Broadcast Joins: Eliminated shuffle overhead for small lookup tables.
  • Partition Pruning: Partitioned S3 outputs by year=YYYY/month=MM/day=DD.
  • Coalesce vs Repartition: Used coalesce() before S3 write to optimize file sizes.
  • Result: Reduced runtime from ~30 mins to 5–6 mins (~80% reduction) and lowered AWS Glue DPU billing costs.

6. Top Interview Preparation Q&As

Q1: How did you use GenAI in your data pipelines?

Answer: "We integrated AWS Bedrock into our AWS observability and data ingestion workflows. For observability, we built a Lambda + Bedrock utility that parses raw Glue/PySpark error tracebacks and sends plain-English root-cause summaries via SNS. For ingestion, we built an LLM schema parser that analyzes dynamic vendor headers and auto-generates JSON mapping configs."

Q2: How did you handle API batching & partial successes?

Answer: "Step Functions orchestrated Glue jobs that grouped staged records into batches of 150. Lambda invoked the Claims API for each batch, persisted responses to S3, and handled partial successes — committing valid claims to Db2/Aurora while storing invalid records with error codes for correction."

Q3: How did you optimize PySpark job performance?

Answer: "We eliminated Spark shuffle bottlenecks using broadcast joins for lookup tables, optimized S3 write partitioning, tuned shuffle partitions, and used coalesce before writing files, reducing runtime from 30 minutes down to 5-6 minutes."
