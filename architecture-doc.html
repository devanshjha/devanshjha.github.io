2. Detailed Step-by-Step Functional Walkthrough

STEP 01
File Ingestion via AWS Transfer Family (SFTP)
Raw multi-vendor data files (CSV, XLSX, ZIP, DAT) deposited by the FMH team from their on-premise shared network path directly into Amazon S3.
Technology: AWS Transfer Family, SFTP, Amazon S3
Destination Path: s3://prudential-data-lake-prod/vendor_a/inbound/
STEP 02
Job Initialization & Inbound-to-Source File Movement
Triggered by AutoSys/CloudWatch Events with category=stageload and vendor_id=VENDOR_A. Moves inbound file to source/ folder to prevent re-triggering.
Technology: AWS Glue (PySpark), Boto3, S3
Destination Path: s3://prudential-data-lake-prod/vendor_a/source/
STEP 03
Dynamic JSON Config Fetching & Schema Resolution
Reads external JSON configuration file on S3. Dynamically resolves target column names, data types, date formats (yyyy-MM-dd), and delimiters — enabling onboarding of new vendors with zero PySpark code changes.
Technology: PySpark, JSON, Amazon S3
Config Path: s3://prudential-data-lake-prod/configs/vendor_a_claims_config.json
STEP 04
PySpark Transformation & Staging Write
Casts data types, formats dates, filters invalid rows, and appends validated records into Db2/Aurora staging table via JDBC using credentials from AWS Secrets Manager.
Technology: PySpark SQL, JDBC, IBM Db2 / AWS Aurora
Staging Table: STG_DISABILITY_CLAIMS
STEP 05
Step Functions State Machine Trigger
AWS Step Functions orchestrates sequential batch generation, REST API calls, exponential backoff retries, and database creation jobs.
Technology: AWS Step Functions State Machine
Trigger: Successful execution of Glue Job 1
STEP 06
Batch Generation (150 Records / Batch)
Reads staged records from STG_DISABILITY_CLAIMS, partitions records into chunks of 150 records per batch, and writes JSON request payloads to S3.
Technology: PySpark Glue Job 2, Amazon S3
Batch Output Path: s3://prudential-data-lake-prod/vendor_a/batch_req/batch_001.json
STEP 07
AWS Lambda REST API Invocation
Triggered by S3 object creation in batch_req/. Retrieves OAuth Token from AWS Secrets Manager and POSTs 150-record JSON payload to Claims REST API.
Technology: AWS Lambda (Python), AWS Secrets Manager, REST API
Payload Size: 150 records per HTTP POST
STEP 08
Partial-Success Response Parsing & S3 Persistence
Parses API response per claim. Successful claims (with assigned Control Number & Claim ID) and failed claims are separated into JSON arrays and written to S3.
Technology: AWS Lambda, Amazon S3
Response Path: s3://prudential-data-lake-prod/vendor_a/batch_resp/batch_001_resp.json
STEP 09
Db2 Stored Procedure Execution & Aurora Table Writes
Reads API response JSONs from batch_resp/. Connects via JDBC, executes reworked IBM Db2 Stored Procedure (SP_PROCESS_CLAIM_CREATION), and inserts valid claims into main table.
Technology: PySpark Glue Job 3, JDBC, IBM Db2, AWS Aurora
Main Table: DISABILITY_CLAIMS
STEP 10
History Load & Idempotent Cleanup
Moves processed stage records to HIST_DISABILITY_CLAIMS along with batch ID and timestamp. Archives source files to ensure idempotent reruns.
Technology: PySpark, Db2/Aurora, S3 Boto3
History Table: HIST_DISABILITY_CLAIMS
STEP 11
AWS Bedrock AI Diagnostics (On Failure)
CloudWatch Alarm triggers Lambda on Glue/Step Function failure. Lambda extracts failure logs and invokes AWS Bedrock (Claude 3) to generate plain-English root cause summaries sent to Slack/Email via SNS.
Technology: AWS Bedrock (Claude 3), Lambda, CloudWatch, SNS
Alert Target: Engineering Slack Channel / Email Digest
