2. S3 Directory Layout & FMH Transfer Integration

The FMH (File Management Handler) team pushes daily insurance vendor feeds via SFTP using AWS Transfer Family directly into our S3 buckets:

s3://prudential-data-lake-prod/
├── configs/          <-- JSON mapping configurations
├── vendor_a/
│   ├── inbound/     <-- FMH deposits files here (CSV, XLSX, ZIP, DAT)
│   ├── source/      <-- PySpark script moves files here for processing
│   ├── batch_req/   <-- 150-record JSON API request payloads
│   ├── batch_resp/  <-- Lambda writes API JSON responses here
│   ├── archive/     <-- Processed files
│   └── error/       <-- Failed files

3. Dynamic PySpark Ingestion Engine

Ingestion logic is completely parameter-driven. Vendor schemas, delimiters, and target tables are defined in JSON configs in S3:

// Example JSON Config (configs/vendor_a_claims_config.json)
{
  "vendor_id": "VENDOR_A",
  "process_type": "disability_claims",
  "source_file_pattern": "claims_*.csv",
  "delimiter": ",",
  "has_header": true,
  "stage_table": "STG_DISABILITY_CLAIMS",
  "columns": [
    {"source_name": "policy_no", "target_name": "POLICY_NO", "type": "string"},
    {"source_name": "ssn_num", "target_name": "SSN", "type": "string"},
    {"source_name": "inc_dt", "target_name": "INCURRAL_DATE", "type": "date", "format": "yyyy-MM-dd"},
    {"source_name": "claim_amt", "target_name": "CLAIM_AMOUNT", "type": "double"}
  ]
}

4. Step Functions, 150-Record Batching & REST API

  • Glue Batch Generator: Reads staged records and chunks them into JSON files containing 150 records per batch written to s3://.../batch_req/.
  • Lambda API Invoker: Reads the 150-record JSON payload from S3, retrieves Auth Token from AWS Secrets Manager, and calls the Claims REST API.
  • Partial-Success Handling: Lambda parses API responses per claim. Valid claims (returning Control Number & Claim ID) and failed claims are separated and persisted to s3://.../batch_resp/.
  • Db2 / Aurora Glue Job: Reads response JSONs, executes IBM Db2 Stored Procedures via JDBC, updates Aurora tables, and moves stage records to history tables to ensure idempotency.

5. Flyway & GitHub Actions CI/CD Pipeline

Database table DDL and stored procedure updates are version-controlled in a Flyway repository:

  • Pushing/merging to feature branch triggers GitHub Actions to run flyway migrate against Dev Aurora/Db2.
  • Merging to sandbox branch triggers GitHub Actions to run flyway migrate against QA Aurora/Db2.

6. GenAI Implementation (AWS Bedrock + Lambda)

1. AI Failure Log Diagnostic Utility

When a Glue job or Step Function fails, EventBridge invokes a Lambda function that extracts the CloudWatch log stream and passes it to AWS Bedrock (Claude 3 model).

🚨 Sample SNS Alert Output:
• Root Cause: SchemaMismatchException — Column incurral_date format expected YYYY-MM-DD but received MM/DD/YYYY.
• Affected Source: s3://prudential-data-lake-prod/vendor_a/inbound/claims_20260924.csv
• Recommended Fix: Update JSON mapping config for Vendor A or request vendor re-format.

2. LLM-Assisted Schema Parser Utility

Bedrock inspects raw incoming vendor file headers (CSV/XLSX) in S3 and auto-suggests candidate JSON mapping configs for developer PR review, reducing vendor onboarding time from hours to seconds.

8. Key Interview Q&A for Technical Cross-Examination

Q1: How do you handle file arrival from the FMH team?
The FMH team runs daily on-premise scheduled jobs pushing files into s3://.../inbound/ using SFTP via AWS Transfer Family. CloudWatch EventBridge or AutoSys cron triggers our parameterized PySpark Glue jobs, passing vendor_id and process_type.
Q2: Why did you use 150-record batching for REST API calls?
Calling the Claims API for 100,000 records individually caused severe network latency and rate limiting, while sending all 100,000 records in one payload exceeded HTTP payload size and timeout limits. 150 records per batch was the sweet spot for throughput and stability.
Q3: How does Flyway + GitHub Actions manage database deployments across Dev & QA?
DDL scripts are version-controlled in Flyway (`V1.x__...sql`). Merging to `feature` branch triggers GitHub Actions to execute Flyway migrations on the Dev database, while merging to `sandbox` branch deploys Flyway migrations to QA.
Q4: How does your AWS Bedrock AI Log Diagnostic work?
When a Glue job fails, EventBridge triggers a Lambda that fetches the CloudWatch stack trace, passes it to AWS Bedrock (Claude 3) with a specialized system prompt, and Bedrock generates a 3-bullet diagnosis (Root Cause, Affected File, Recommended Fix) sent via SNS to engineers.
